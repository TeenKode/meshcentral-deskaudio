# Changelog

## 0.8.0

* Качество ADPCM: кодер подбирает стартовый шаг квантования по динамике блока — убирает периодическое
  искажение/«шум» на границах чанков (раньше каждый блок начинался с нулевого шага и «догонял» сигнал).
* Переключатель **«Сжатие звука»** во вкладке «Звук»: выключите для сырого PCM (максимальное качество, больше
  трафика), включите для ADPCM (экономия трафика). Запоминается в браузере; по умолчанию включено. Действует
  со следующего старта прослушивания.
* Подпись хелпера кэшируется: сервер подписывает бинарник один раз и переиспользует (пока не изменится exe или
  сертификат), поэтому хеш/`.ver` больше не «дрожит» при каждом рестарте сервера.

## 0.7.0

* Сжатие звука **IMA ADPCM (~4:1)** без внешних библиотек: ≈ 32 / 64 / 96 кбит/с вместо 128 / 256 / 384.
  Кодирование на агенте, декод в браузере; каждый чанк — самодостаточный блок (потеря пакета не
  рассинхронизирует поток). В протоколе добавлен маркер `codec`; PCM поддерживается как запасной путь.
* Тест сквозного прохода ADPCM (реальный кодер агента ↔ реальный декодер браузера).

## 0.6.0

* Подавление тишины: агент не передаёт «тихие» чанки (ниже порога), экономя трафик, когда на удалённой
  машине ничего не играет.
* Серверный лимит одновременных аудиопотоков (захватываемых устройств) — `MAX_TOTAL_STREAMS = 50`.
* Громкость запоминается в браузере между сессиями.
* CI: GitHub Actions гоняет `npm test` на каждый push и pull request.
* Добавлены тесты: определение тишины (`_isSilent`) и server-wide лимит.

## 0.5.0

* Индикатор прослушивания в панели «Рабочий стол»: зелёная точка рядом со штатным индикатором записи
  (`deskRecordIcon`), горит, пока идёт приём звука.
* Надёжность при обрывах:
  * клиентский таймаут — состояние «Подключение…» больше не висит вечно, если агент не отвечает (~10 с →
    сброс с сообщением);
  * сервер шлёт агенту `stop`, если получил звук/статус по устройству без слушателей (например, после
    перезапуска сервера) — не копятся «осиротевшие» захваты;
  * сброс `gotAudio` при каждом старте, очистка таймера подключения при старте/стопе/статусе/первом чанке.
* Звук привязан к рабочему столу: при отключении стола (`onDesktopDisconnect`) прослушивание прекращается
  в любом режиме (не только в авто).
* Лимит одновременных слушателей на устройство увеличен с 3 до 10.

## 0.4.0

* Кнопка 🔊 вкл/выкл звука прямо во вкладке «Рабочий стол» — через штатный слот MeshCentral
  `desktopCustomUiButtons` (не хак по DOM).
* Галочка «Слушать звук при подключении к рабочему столу»: звук стартует при нажатии Connect и
  останавливается по `onDesktopDisconnect`. Запоминается в браузере, по умолчанию выключена.

## 0.3.0

* Сервер подписывает нативные хелперы тем же code-signing сертификатом, которым MeshCentral подписывает
  агентов (`obj.certificates.codesign`, модуль `authenticode.js`) — хелпер получает того же издателя, что и
  агент. Best-effort: без сертификата/модуля хелперы раздаются без подписи. Уровень доверия = как у агентов
  (дефолтный самоподписанный ОС не доверяет; для доверия нужен настоящий CA `agentsigningcert.pem`).

## 0.2.1

* Хелпер теперь сохраняется и запускается из папки агента (`C:\Program Files\Mesh Agent\
  deskaudio-helper.exe`) под стабильным именем, а не из `%TEMP%`. Папка агента обычно уже в исключениях
  антивируса (Dr.Web и т.п. вайтлистят агента по пути), поэтому хелпер наследует это исключение; при
  необходимости достаточно один раз добавить один стабильный путь. Фолбэк на `%TEMP%`, если папка агента
  недоступна для записи.

## 0.2.0

* Windows: теперь используется **готовый нативный хелпер** (`deskaudio-x64.exe` / `deskaudio-x86.exe`,
  исходник `win-loopback-native.cpp`) — без .NET и без компиляции на целевой машине. Статическая линковка,
  зависимости только системные (`kernel32`, `msvcrt`, `ole32`). Полная совместимость 32/64-бит, Windows 7…11.
* Компиляция `win-loopback.cs` через `csc.exe` оставлена как запасной путь, если положить exe не удалось.
* Добавлен `helpers/build-native.sh` для пересборки бинарников (MinGW-w64).

## 0.1.1

* Windows 7 и старые системы: хелпер теперь собирается любым встроенным `csc.exe` — поиск по
  `v4.0.30319 → v3.5 → v2.0.50727` (обе разрядности). .NET 3.5 / 2.0 встроены в Windows 7 по умолчанию,
  так что .NET Framework 4 больше не обязателен. Исходник `win-loopback.cs` ограничен C# 2.0.

## 0.1.0

* Первая версия. Вкладка «Звук» на странице устройства: передача звука рабочего стола удалённого
  компьютера в браузер в реальном времени.
* Windows — WASAPI loopback (хелпер собирается на месте через `csc.exe` из .NET Framework 4).
* Linux — `parec` (PulseAudio / PipeWire) с монитора текущего устройства вывода.
* Требуется право «Удалённое управление» на устройство; каждое включение пишется в журнал событий.
