# Desktop Audio — плагин MeshCentral

Слушать в браузере звук, который играет на удалённом компьютере (то, что идёт на его динамики), в реальном времени.
Вкладка **«Звук»** появляется у каждого устройства.

## Как работает

    браузер ──start──▶ сервер ──start──▶ агент
    браузер ◀─PCM──── сервер ◀─PCM───── агент (захват звука)

* **Windows** — WASAPI loopback. Плагин присылает агенту исходник `helpers/win-loopback.cs`, агент один раз
  собирает его встроенным `csc.exe` (.NET Framework 4, есть в любой Windows 10/11) в `%TEMP%`.
* **Linux** — `parec` (пакет `pulseaudio-utils`; работает и с PipeWire через pipewire-pulse), запускается от имени
  вошедшего пользователя через `runuser`.
* **macOS** — не поддерживается (нужен виртуальный драйвер вроде BlackHole).
* Формат: mono, 16-bit PCM, 8/16/24 кГц (выбирается во вкладке), ≈ 128 / 256 / 384 кбит/с.
  Задержка порядка 200–300 мс.

## Установка

Сверено с исходниками MeshCentral 1.2.6 (pluginHandler.js, meshuser.js, meshagent.js, agents/meshcore.js).

1. В `meshcentral-data/config.json`: `"plugins": { "enabled": true }`, перезапустить MeshCentral.
2. **Вариант B — через интерфейс (рекомендуется).** My Server → Plugins → Download plugin → вставить URL
   `config.json`:

       https://raw.githubusercontent.com/TeenKode/meshcentral-deskaudio/main/config.json

   MeshCentral сам скачает zip репозитория (`downloadUrl`), распакует его, срезав верхнюю папку архива, и
   положит файлы в `meshcentral-data/plugins/deskaudio/`. Останется включить плагин в списке и обновить
   страницу. Ничего в `config.json` править не нужно — ссылки уже настроены на этот репозиторий.
3. **Вариант A — вручную, без GitHub.** Скопировать содержимое репозитория в `meshcentral-data/plugins/deskaudio/`
   (так, чтобы `config.json` и `deskaudio.js` лежали прямо в этой папке) и добавить в настройки
   `"plugins": { "enabled": true, "list": ["deskaudio"] }` (режим для локальной разработки: плагин берётся из
   папки, а не из базы). Перезапустить MeshCentral.
4. Модуль агента попадает в ядро при старте сервера (`updateMeshCore`). Агентам новое ядро приходит при
   переподключении. Если вкладка работает, а звука нет, обновите ядро принудительно из консоли браузера
   (под администратором):

       meshserver.send({action:'uploadagentcore', type:'default', nodeids:['node//…']});

## Права и доступ

* Передачу звука может включить только пользователь с правом **«Удалённое управление»** на устройство —
  то же право, что нужно для удалённого рабочего стола и терминала.
* Каждое включение пишется в журнал событий устройства.
* Как и у остальных сессий удалённого доступа в MeshCentral, передача включается вручную из панели устройства,
  так что активная сессия видна администратору. Настройте использование плагина согласно политикам вашей
  организации и применимому законодательству.
* Если слушатель закрыл вкладку, агент останавливает захват; если пропала связь с сервером — через 60 секунд.

## Ограничения / что проверить на месте

* Если на машине ничего не играет, WASAPI не отдаёт данные — в браузере просто тишина (так и должно быть).
* Windows: агент работает как служба (сессия 0). Loopback по идее работает и оттуда, но если звука нет — в
  `modules_meshcore/deskaudio.js` поставьте `SPAWN_AS_USER = true` (хелпер запустится в сессии пользователя).
* Linux: если вошло несколько пользователей, берётся первый с активным аудио-сокетом в `/run/user`.
* Звук идёт через управляющий канал агента (JSON + base64), поэтому для 24 кГц канал до сервера должен быть не уже ~0.5 Мбит/с.

## Структура репозитория

`config.json` и `deskaudio.js` лежат в **корне репозитория** (рядом — `modules_meshcore/`, `helpers/`,
`changelog.md`), как и у большинства плагинов MeshCentral (например
[MeshCentral-Sample](https://github.com/ryanblenis/MeshCentral-Sample)). Это нужно для установки через
интерфейс: MeshCentral скачивает GitHub-архив репозитория, при распаковке отбрасывает верхнюю папку архива
(`meshcentral-deskaudio-main/`) и ожидает `config.json` сразу под ней. `package.json` и тесты (`test/`) в
архив тоже попадают, но MeshCentral их игнорирует.

## Тесты

Серверная логика, браузерный декодер PCM и манифест покрыты тестами на встроенном в Node раннере
(`node:test`), без внешних зависимостей и без сети:

    npm test        # или: node --test

Что проверяется:

* **`test/server.test.js`** — маршрутизация `serveraction` (браузер ↔ агент), проверка права «удалённое
  управление», офлайн-устройство, лимит слушателей, старт/стоп захвата, ретрансляция аудио-чанков,
  завершение потока по ошибке агента, keepalive при обрыве связи, отбрасывание звука при переполнении буфера
  браузера (но не статусов), очистка при закрытии вкладки.
* **`test/browser-onchunk.test.js`** — декодирование s16le little-endian PCM в нормализованные float,
  джиттер-буфер и отбрасывание «опоздавших» чанков, игнорирование чужих нод и пустых пакетов.
* **`test/config.test.js`** — корректность `config.json`, соответствие `shortName` папке и файлу, наличие
  всех файлов, которые плагин подгружает в рантайме, и состав браузерных экспортов.

Сигнатуры (`serveraction(command, obj, parent)` для браузера и агента, `agent.dbNodeKey`, `wsagents`) сверены
с исходниками MeshCentral (`meshuser.js`, `meshagent.js`, `pluginHandler.js`).
